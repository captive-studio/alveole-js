# Migration vers Alveole 2.0

Guide destiné à être donné tel quel à un agent IA (ou suivi à la main) pour migrer une application
de `@alveole/*` 1.10 vers 2.0. Chaque section donne : **comment trouver** les appels, **comment les
réécrire**, et les **pièges** qui font échouer le typecheck ou changent le comportement.

Aucun alias n'est conservé : tout ce qui est retiré casse au typecheck. Le typecheck est donc la
liste de travail de référence.

## Procédure

1. Mettre à jour les paquets en version exacte :
   `@alveole/components`, `@alveole/core`, `@alveole/theme`, `@alveole/storybook`,
   `@alveole/eslint-config` → `2.0.0`.
2. Mettre à jour les peer dependencies (section [Dépendances](#1-dépendances)).
3. Lancer les recherches `git grep` de chaque section, appliquer les réécritures **section par
   section** (l'ordre du document est l'ordre conseillé : les champs avant les icônes, car un même
   appel est souvent concerné par les deux).
4. Lancer le typecheck du projet. Chaque erreur restante correspond à une ligne d'un tableau
   ci-dessous.
5. Lancer les tests et vérifier visuellement les formulaires (libellé, erreur, bordure rouge).

Règle générale à retenir : **un champ ne porte plus son libellé**. Le libellé, l'aide (`hint`) et
le message (`error` / `success`) vont sur `FormControl`, le contrôle nu va dedans.

```tsx
<FormControl label="…" hint="…" error={error} required>
  <Controle … error={error} />
</FormControl>
```

`error` est passé **aux deux** : `FormControl` affiche le message sous le champ, le contrôle colore
sa bordure. Avant, le `*Field` faisait les deux tout seul.

## 2. Champs de saisie `*Field` → `FormControl` + contrôle

```bash
git grep -nE "\b(TextField|TextareaField|EmailField|EmailInput|PasswordField|PhoneField|PhoneInput|NumberField|OtpField|FileField|FormControlNumberInput|FormControlOtpInput|FormControlFileInput)\b"
```

| Avant                                              | Après (dans un `FormControl`)                                           |
| -------------------------------------------------- | ----------------------------------------------------------------------- |
| `TextField`                                        | `TextInput`                                                             |
| `TextareaField`                                    | `TextareaInput`                                                         |
| `EmailField`, `EmailInput`                         | `TextInput type="email"`                                                |
| `PasswordField`                                    | `TextInput type="password"`                                             |
| `PhoneField`, `PhoneInput`                         | `TextInput type="tel"`                                                  |
| `NumberField`, `FormControlNumberInput`            | `NumberInput`                                                           |
| `OtpField`, `FormControlOtpInput`                  | `OtpInput`                                                              |
| `FileField`, `FormControlFileInput`                | `FileInput`                                                             |
| type `FileFieldValue`, `FormControlFileInputValue` | `FileInputValue`                                                        |
| types `*FieldProps`                                | `TextInputProps`, `NumberInputProps`, `OtpInputProps`, `FileInputProps` |

Props qui **montent sur `FormControl`** : `label`, `labelRight`, `hint`, `error`, `success`,
`required`, `disabled` (et `disabled` reste aussi sur le contrôle).
Tout le reste reste sur le contrôle.

### Piège n°1 : `onChange` des champs texte

Les anciens `TextField`, `TextareaField`, `EmailField`, `PasswordField`, `PhoneField`, `PhoneInput`
avaient un alias `onChange(text: string)`. **Il disparaît** : `TextInput` reprend les props de
React Native, où `onChange` reçoit un **événement**, pas une chaîne. Le typecheck ne le signale
pas toujours (ex. `onChange={setValue}` avec un `setState` non typé).

➡️ Sur `TextInput` / `TextareaInput` : **renommer systématiquement `onChange` en `onChangeText`.**

Ne concerne **pas** `NumberInput`, `OtpInput`, `FileInput`, `Select`, `DateInput`, `TimeInput`,
`DurationInput` : leur `onChange` reçoit toujours la valeur.

### Piège n°2 : réglages imposés retirés

`TextField` forçait `autoComplete="off"`, `textContentType="none"`, `autoCapitalize="sentences"`.
`TextInput` ne force plus rien. Si un champ doit rester sans remplissage automatique, l'écrire
explicitement : `<TextInput autoComplete="off" textContentType="none" />`.
`type="text"` et `type="hidden"` de `TextField` n'avaient aucun effet :
retirer `type="text"` (valeur par défaut de `TextInput`) et `type="hidden"`, sans autre changement.
`type="hidden"` n'a jamais masqué le champ (ignoré en natif, réécrit en `type="text"` par react-native-web) :
si un appel comptait dessus pour cacher une valeur, ne pas rendre le champ (`{visible && <TextInput … />}`).

### Exemples

```tsx
// Avant
<TextField
  label="Nom"
  hint="Tel qu'il apparaît sur la pièce d'identité"
  placeholder="Jean Dupont"
  value={nom}
  onChange={setNom}
  error={errors.nom}
/>

// Après
<FormControl label="Nom" hint="Tel qu'il apparaît sur la pièce d'identité" error={errors.nom}>
  <TextInput placeholder="Jean Dupont" value={nom} onChangeText={setNom} error={errors.nom} />
</FormControl>
```

```tsx
// Avant
<EmailField label="Email" value={email} onChange={setEmail} />
<PasswordField label="Mot de passe" value={password} onChange={setPassword} />
<PhoneField label="Téléphone" value={tel} onChange={setTel} />

// Après
<FormControl label="Email">
  <TextInput type="email" value={email} onChangeText={setEmail} />
</FormControl>
<FormControl label="Mot de passe">
  <TextInput type="password" value={password} onChangeText={setPassword} />
</FormControl>
<FormControl label="Téléphone">
  <TextInput type="tel" value={tel} onChangeText={setTel} />
</FormControl>
```

```tsx
// Avant
<TextareaField label="Message" numberOfLines={4} value={msg} onChange={setMsg} />

// Après
<FormControl label="Message">
  <TextareaInput numberOfLines={4} value={msg} onChangeText={setMsg} />
</FormControl>
```

```tsx
// Avant
<NumberField label="Montant" value={montant} onChange={setMontant} error={err} />

// Après — onChange inchangé : (value: number | null) => void
<FormControl label="Montant" error={err}>
  <NumberInput value={montant} onChange={setMontant} error={err} />
</FormControl>
```

```tsx
// Avant
<OtpField label="Code reçu" numberOfDigits={6} onChange={setCode} />

// Après — onChange inchangé
<FormControl label="Code reçu">
  <OtpInput numberOfDigits={6} onChange={setCode} />
</FormControl>
```

```tsx
// Avant
const [file, setFile] = useState<FileFieldValue>(null);
<FileField label="Justificatif" type="application/pdf" value={file} onChange={setFile} />;

// Après — la vérification du type de fichier (alerte « Type de fichier incorrect ») est conservée dans FileInput
const [file, setFile] = useState<FileInputValue>(null);
<FormControl label="Justificatif">
  <FileInput type="application/pdf" value={file} onChange={setFile} />
</FormControl>;
```

Si un `ref` était passé au `*Field`, le passer au contrôle (`<TextInput ref={ref} />`).

### `TextareaInput` (le composant existe toujours)

En 1.10, son type reprenait celui de `TextField` : `label` y était **obligatoire**, et `hint`,
`labelRight`, `optional`, `onChange` acceptés… mais **aucun n'était affiché ni branché**. Les appels
existants passent donc presque tous un `label` invisible. Ces props n'existent plus.

```bash
git grep -nE "<TextareaInput\b"
```

- `label` / `hint` : les déplacer sur un `FormControl` autour. ⚠️ Changement visuel : le libellé
  devient visible. S'il ne doit pas l'être (libellé déjà affiché ailleurs), supprimer simplement la
  prop.
- `onChange` : ne fonctionnait pas avec une chaîne (React Native lui passait un événement) ;
  renommer en `onChangeText`.

```tsx
// Avant
<TextareaInput label="Commentaire" value={c} onChangeText={setC} />

// Après (libellé visible)
<FormControl label="Commentaire">
  <TextareaInput value={c} onChangeText={setC} />
</FormControl>
```

### `FormControlLabel` et `RadioGroup` : `optional` / `optionalText` supprimés

La mention « (optionnel) » disparaît au profit de l'astérisque sur les champs **requis**.

```bash
git grep -nE "\boptional(Text)?[=:]"
```

| Avant                                        | Après                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `optional` / `optionalText="…"`              | retirer ; marquer à l'inverse les champs obligatoires : `<FormControl required>`           |
| `<FormControlLabel error="…" success="…" />` | retirer `error`/`success` (le libellé ne se colore plus) ; message via `FormControl error` |
| `<RadioGroup label=… optional />`            | retirer `optional` (`label` devient facultatif)                                            |

  <TimeInput value={heure} onChange={setHeure} />

## 4. `Select`, `SelectMultiple`, `Autocomplete`, `AutocompleteAddress` → `Select`

```bash
git grep -nE "\b(Select|SelectMultiple|SelectInput|NativePicker|Autocomplete|AutocompleteChip|AutocompleteAddress|AutocompleteOption\w*|SelectMultipleOption)\b"
```

Le nouveau `Select` couvre tous les cas : simple, multiple, recherche (locale ou distante),
création. Il est **nu** (dans un `FormControl`) et **strictement contrôlé**.

Types exportés : `SelectOption` (`{ value: string; label: string; leading?; group?; disabled? }`),
`SelectProps`, `SelectRef`, `SelectItem`. Supprimés : `NativePicker`, `SelectInput`,
`SelectMultipleOption`, `AutocompleteOption*`, `isAutocompleteOptionWithGroup*`.

### 4.1 `Select` simple

```tsx
// Avant
<Select label="Pays" hint="…" options={pays} value={code} onChange={setCode} error={err} />

// Après
<FormControl label="Pays" hint="…" error={err}>
  <Select options={pays} value={code} onChange={setCode} error={err} />
</FormControl>
```

`value: string | null`, `onChange(value: string | null)` : inchangés. Ajouter `clearable` si
l'utilisateur doit pouvoir revenir à « aucune valeur ». Le titre du bottom sheet mobile est par
défaut le `label` du `FormControl` (sinon `sheetTitle`).

### 4.2 `SelectMultiple` → `Select multiple`

```tsx
// Avant
<SelectMultiple label="Rôles" options={roles} value={ids} onChange={setIds} />

// Après
<FormControl label="Rôles">
  <Select multiple options={roles} value={ids} onChange={setIds} />
</FormControl>
```

Piège : `value` doit être un `string[]` (plus de `number`) et **obligatoire** (passer `[]`, pas
`undefined`). Les `value` numériques des options deviennent des chaînes :
`options.map(o => ({ ...o, value: String(o.value) }))`, et reconvertir dans `onChange` si besoin.

### 4.3 `Autocomplete` → `Select`

| Autocomplete                  | Select                                                                                        |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| `value: AutocompleteOption[]` | `value: string \| null` (simple) / `string[]` (`multiple`) — **des valeurs, plus des objets** |
| `isMulti`                     | `multiple`                                                                                    |
| `isSearchable`                | `searchable`                                                                                  |
| `disabledFilterSearch`        | `localFilter={false}`                                                                         |
| `disabledSearch`              | retirer `searchable`                                                                          |
| `allowEmpty`                  | `clearable`                                                                                   |
| `allowCreate`                 | `creatable` (implique `searchable`)                                                           |
| `onCreateOption(option)`      | `onCreateOption(query: string)` — l'appelant crée l'option                                    |
| `createOptionLabel`           | `createLabel`                                                                                 |
| `createOptionValue`           | supprimé : l'appelant fabrique `value` dans `onCreateOption`                                  |
| `onChange(options, meta)`     | `onChange(value)` — plus de second argument `meta`                                            |
| `onSearchChange`              | `onSearchChange` (émis après 300 ms, jamais au montage)                                       |
| `label`, `hint`, `error`      | sur `FormControl` (et `error` aussi sur `Select`)                                             |
| `autoFocus`                   | `ref` (`SelectRef.open()` / `focus()`) dans un `useEffect`                                    |
| option `{ group }`            | inchangé : options consécutives de même `group` regroupées                                    |

Conversion de la valeur, le point qui demande le plus d'attention :

```tsx
// Avant : l'état contenait des objets option
const [selected, setSelected] = useState<AutocompleteOption[]>([]);
<Autocomplete label="Client" isSearchable options={clients} value={selected} onChange={setSelected} />;
// lecture : selected[0]?.value

// Après : l'état contient la valeur
const [clientId, setClientId] = useState<string | null>(null);
<FormControl label="Client">
  <Select searchable options={clients} value={clientId} onChange={setClientId} />
</FormControl>;
// lecture : clientId
// besoin du libellé : clients.find(c => c.value === clientId)?.label
```

```tsx
// Avant : multi + création
<Autocomplete
  label="Étiquettes"
  isMulti
  allowCreate
  options={tags}
  value={selected}
  onChange={(value, meta) => {
    setSelected(value);
    meta?.created.forEach(save);
  }}
/>;

// Après
const [tags, setTags] = useState<SelectOption[]>(initialTags);
const [values, setValues] = useState<string[]>([]);
<FormControl label="Étiquettes">
  <Select
    multiple
    creatable
    options={tags}
    value={values}
    onChange={setValues}
    onCreateOption={query => {
      // obligatoire : ajouter l'option PUIS la sélectionner, sinon rien ne s'affiche
      setTags(current => [...current, { label: query, value: query }]);
      setValues(current => [...current, query]);
      save(query);
    }}
  />
</FormControl>;
```

Recherche distante (anciennement `disabledFilterSearch` + `onSearchChange`) :

```tsx
<FormControl label="Recherche">
  <Select
    searchable
    localFilter={false}
    loading={loading}
    emptyMessage="Saisir au moins 3 caractères"
    options={resultats}
    value={value}
    onChange={setValue}
    onSearchChange={rechercher}
  />
</FormControl>
```

### 4.4 `AutocompleteAddress` → `Select`

| AutocompleteAddress        | Select                                  |
| -------------------------- | --------------------------------------- |
| `suggestions`              | `options`                               |
| `onPlaceSelected(placeId)` | `onChange(value)` avec `value !== null` |
| `onCustomAddress(address)` | `onCreateOption(query)`                 |
| `onClear()`                | `onChange(null)` (avec `clearable`)     |
| `disabledCreation`         | retirer `creatable`                     |
| `label` (défaut "Adresse") | `FormControl label="Adresse"`           |

```tsx
// Avant
<AutocompleteAddress
  value={value}
  suggestions={suggestions}
  error={err}
  onSearchChange={search}
  onPlaceSelected={placeId => selectPlace(placeId)}
  onCustomAddress={address => setCustom(address)}
  onClear={reset}
/>

// Après
<FormControl label="Adresse" error={err}>
  <Select
    placeholder="ex : 3 rue Robespierre"
    searchable
    localFilter={false}
    creatable
    clearable
    emptyMessage="Saisir au moins 3 caractères"
    createLabel={query => `Utiliser « ${query} »`}
    options={suggestions}
    value={placeId}
    error={err}
    onSearchChange={search}
    onChange={value => (value === null ? reset() : selectPlace(value))}
    onCreateOption={address => {
      setSuggestions(current => [...current, { label: address, value: address }]);
      setPlaceId(address);
      setCustom(address);
    }}
  />
</FormControl>
```

Attention : quand la recherche distante remplace `options`, l'option sélectionnée doit rester dans
`options`, sinon son libellé n'est plus affiché dans le champ fermé. Garder l'option retenue en tête
de la liste : `options={[...selectedOption ? [selectedOption] : [], ...suggestions]}`.

## 5. Icônes → `leading` / `trailing`

Détail et justification : [leading-trailing.md](leading-trailing.md).

```bash
git grep -nE "startIcon|endIcon|\bicon[=:]"
```

| Composant                             | Avant                   | Après                  |
| ------------------------------------- | ----------------------- | ---------------------- |
| `Button`                              | `startIcon` / `endIcon` | `leading` / `trailing` |
| `AccordionItem`                       | `startIcon`             | `leading`              |
| `Tag`                                 | `icon`                  | `leading`              |
| `Tabs` (élément de `tabs`), `TabsTab` | `icon`                  | `leading`              |
| `SidebarItem`                         | `icon`                  | `leading`              |
| `ActionMenu.Item`                     | `icon`                  | `leading`              |
| `RadioGroupCard`                      | `icon`                  | `leading`              |
| `DragAndDropFile`                     | `icon`                  | `leading`              |
| `SelectOption`                        | `{ icon }`              | `{ leading }`          |
| `ToastView`, `toast.present(…, opts)` | `icon`                  | `leading`              |

**Ne pas toucher** `icon` sur `ButtonIcon`, `InputButtonAdornment`, `DocumentViewerToolbarButton`,
ni `name` sur `LucideIcon`. Renommage mécanique : la valeur (nom d'icône) ne change pas.

```tsx
<Button variant="secondary" title="Filtres" startIcon="Plus" endIcon="ChevronDown" />
// →
<Button variant="secondary" title="Filtres" leading="Plus" trailing="ChevronDown" />
```

`leading={null}` retire l'icône par défaut de `Toast` et `DragAndDropFile`.

### Noms d'icônes retirés

Le catalogue d'icônes est désormais embarqué dans Alveole. Ces noms ne sont plus acceptés
(`name`, `icon`, `leading`, `trailing`, `IconProps.name`…) :

| Nom                                                              | Remplacement                                                    |
| ---------------------------------------------------------------- | --------------------------------------------------------------- |
| `broom`, `carton`, `cartonOff`, `houses`, `textSquare` (Lab)     | choisir une icône proche dans le catalogue (story `LucideIcon`) |
| `Icon`, `LucideProvider`, `createLucideIcon`, `useLucideContext` | ce n'étaient pas des icônes : retirer                           |

```bash
git grep -nE "['\"](broom|carton|cartonOff|houses|textSquare|Icon|LucideProvider|createLucideIcon|useLucideContext)['\"]"
```

## 6. `Button`, `ButtonIcon`, `Badge`

```bash
git grep -nE "variant=['\"]link['\"]|size=['\"]xs['\"]|\b(noPadding|borderNone|leftAlign)\b|<Button\b[^>]*\bactive\b"
```

| Avant                                                              | Après                                                                            |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| `<Button size="xs" …>`                                             | `size="sm"`                                                                      |
| `<Button variant="link" title="…" onPress={go} />` qui **navigue** | `<Link href="/chemin">…</Link>` (ou `A`)                                         |
| `<Button variant="link" …>` qui **agit** sur place                 | `variant="tertiary"`                                                             |
| `<Button leftAlign …>`                                             | `contentAlign="start"`                                                           |
| `<Button noPadding …>`, `<Button borderNone …>`                    | retirer ; si l'effet était voulu : `variant="tertiary"` ou un `Pressable` maison |
| `<Button active={open} …>`                                         | `expanded={open}` (`active` est déprécié, pas encore supprimé)                   |
| `<Button startIcon="X" />` **sans `title`**                        | `<ButtonIcon variant="…" icon="X" accessibilityLabel="Action décrite" />`        |
| `<ButtonIcon icon="X" />` sans `accessibilityLabel`                | ajouter `accessibilityLabel="…"` (obligatoire)                                   |
| `<Badge variant="disabled" …>`                                     | `variant="default"`                                                              |

`title` est désormais **obligatoire** sur `Button` : toute erreur « Property 'title' is missing »
est un bouton-icône à convertir en `ButtonIcon`. `ButtonIcon` accepte seulement les variantes
`primary`, `secondary`, `tertiary`.

```tsx
// Avant
<Button variant="tertiary" startIcon="Trash" onPress={remove} />
<Button variant="link" title="Voir le dossier" onPress={() => router.push(`/dossiers/${id}`)} />

// Après
<ButtonIcon variant="tertiary" icon="Trash" accessibilityLabel="Supprimer" onPress={remove} />
<Link href={`/dossiers/${id}`}>Voir le dossier</Link>
```

`Link` n'accepte qu'une chaîne en `children`, et `href` + `target` (`target="_blank"` pour un lien
externe dans un nouvel onglet web / navigateur intégré en natif).

## 6 bis. `Tag`, `ToolbarTop`

```bash
git grep -nE "<Tag\b[^>]*\bcolor=|\b(onActions|actionsIcon)\b|onNavigate="
```

| Avant                                      | Après                                                                                         |
| ------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `<Tag color="default" …>`                  | retirer `color` (le Tag est toujours gris)                                                    |
| `<Tag color="action" …>`                   | une couleur porteuse de sens → `Badge` ; un compteur → `Counter`                              |
| `ToolbarTop onActions={…} actionsIcon="X"` | supprimés : passer le bouton dans `actions`                                                   |
| `ToolbarTop onNavigate={…}`                | `navigationLabel` devient **obligatoire** avec `onNavigate` (nom accessible du bouton retour) |

```tsx
// Avant
<ToolbarTop title="Dossier" onNavigate={back} onActions={openMenu} actionsIcon="EllipsisVertical" />

// Après
<ToolbarTop
  title="Dossier"
  onNavigate={back}
  navigationLabel="Retour"
  actions={<ButtonIcon variant="tertiary" icon="EllipsisVertical" accessibilityLabel="Plus d'actions" onPress={openMenu} />}
/>
```

Nouveautés du `Tag`, si utiles : `selected`, `interactive`, `closable` + `onClose`, `leading`.

## 7. `@alveole/theme`

```bash
git grep -nE "\b(Mandarine|Shakespeare|Pacifika|ButteryWhite|CoralRed|Lochmara|BigStone|LimeGreen|Purple)\b|Inter|Barlow|generateDefaultThemeCSS|generateFontSmoothingCSS|color-(sun|950)\b|illustration"
```

| Avant                                                                                                                    | Après                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rampes `Mandarine`, `Shakespeare`, `Pacifika`, `ButteryWhite`, `CoralRed`, `Lochmara`, `BigStone`, `LimeGreen`, `Purple` | supprimées : choisir la rampe restante la plus proche (ou copier la valeur hex localement)                                                                                                                                                                                                           |
| Polices Inter (corps) et Barlow                                                                                          | tout est en **Geist** : `'Inter-Light' / 'Inter-Regular' / 'Inter-Medium' / 'Inter-Bold'` et `'Barlow-*'` → `'Geist-Light' / 'Geist-Regular' / 'Geist-Medium' / 'Geist-Bold'` (clés de `FontsMap`, `FontWeightMap`, `fontStyle(…)`) ; retirer `@expo-google-fonts/inter` / `barlow` si plus importés |
| Palette `illustration` imbriquée (`illustration["color-sun"].default.yellow`, idem `color-950`)                          | clés aplaties : `color-sun-default-yellow`, `color-950-default-yellow`                                                                                                                                                                                                                               |
| `generateDefaultThemeCSS()`                                                                                              | `generateThemeCSSParts(theme).join('\n')`                                                                                                                                                                                                                                                            |
| `generateFontSmoothingCSS()`                                                                                             | supprimé : plus d'antialiasing global. Le recréer côté app seulement si nécessaire.                                                                                                                                                                                                                  |
| `injectVariableCSS(theme: Theme)`, `generateCSSVariables(theme: Theme)`                                                  | même appel ; le paramètre est typé `SourceDuCSS` (un `Theme` reste accepté s'il fournit les mêmes clés)                                                                                                                                                                                              |
| `Radius` / `Box.borderRadius` : `number`                                                                                 | `number \| 'var(--radius-…)'` sur web : ne plus faire de calcul sur un rayon du thème                                                                                                                                                                                                                |

Les clés de spacing dépréciées existent toujours (non cassant) mais leurs usages sont à migrer vers
l'échelle V/W quand on y passe.

## 8. Vérification finale

```bash
git grep -nE "\b(TextField|TextareaField|EmailField|EmailInput|PasswordField|PhoneField|PhoneInput|NumberField|OtpField|FileField|SelectMultiple|Autocomplete\w*|NativePicker|SelectInput)\b|startIcon|endIcon|variant=['\"]link['\"]|size=['\"]xs['\"]|noPadding|borderNone|leftAlign|\boptional(Text)?[=:]|onActions|actionsIcon|<Tag\b[^>]*\bcolor=|Inter-|Barlow-"
```

Doit ne rien renvoyer. Puis : typecheck, lint, tests. Points à contrôler à l'œil :

- chaque champ en erreur a **le message** (`FormControl error`) **et la bordure rouge** (`error` du contrôle) ;
- aucun `TextInput` avec `onChange=` (doit être `onChangeText=`) :
  `git grep -nE "<(TextInput|TextareaInput)\b[^>]*\bonChange="` ;
- les `Select` multiples et créables affichent bien la valeur sélectionnée après création.
